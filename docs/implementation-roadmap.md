## Full completion requirements

1. Nested validation with patient-group isolation; preprocessing, feature selection, hyperparameters, panel size and thresholds learned inside training partitions only.
2. Frozen, versioned model artifacts; binary outcome labels; survival baseline hazard, time units and fixed risk thresholds; identical single/batch and saved/restored predictions.
3. Robust CSV and preflight QC: duplicate IDs/groups, missingness, numeric/categorical roles, constant genes, class/event counts, survival times/horizon, impossible splits and frequency settings.
4. Unique run directories, atomic manifests, artifact validation, meaningful failed/partial/cancelled states, input/config/engine/environment/evidence provenance and compatible checkpoint resume.
5. External cohort evaluation with no refitting and an input-distribution comparison.
6. Clinical-only, genes-only and combined models on identical folds; stepwise and elastic-net logistic/Cox comparisons.
7. Small-panel tradeoffs; outer-fold selection and coefficient-direction stability and panel overlap.
8. ROC/PR-AUC, sensitivity/specificity, calibration, Brier, DCA, uncertainty; survival concordance, time-dependent discrimination and calibration, survival probabilities and KM views.
9. Persistent experiment history, run comparison and resume; bounded parallel workers with deterministic resampling.
10. HTML and PDF research reports with methods, exclusions, validation, metrics, gene signatures, figures, limitations and provenance, informed by TRIPOD+AI reporting items.
11. Gene evidence explorer linking stability, direction, Open Targets evidence, pathway and PPI; interactive network inspection.
12. ORA background universe reflecting measured/eligible genes; separate original/expanded sets; explicit STRING expansion, mapping coverage and ranked GSEA.
13. Shared configuration schema/defaults, modular R engine, predictions reused by all metrics/figures, reproducible runtime versions and PR-level scientific/GUI/Rust integration tests.
14. Full executable CLI workflows and AGENTS.md/CLAUDE.md instructions; maintain existing entrypoint compatibility and document migration.

## Shared engine contract

- Root `BiomarkerCLI.R` loads `R/load.R`, which sources independent modules from the repository location, never from the user's data directory.
- `config/schema.json` defines version 1 nested binary/survival configuration and common defaults. Legacy YAML remains accepted through normalization. Runtime functions use a flat normalized list with snake_case keys and `analysis_type`.
- Public R functions use `bmp_` prefixes. Errors are actionable and unavailable numerical values remain missing with reason fields.
- New output lives under `<output_dir>/runs/<run_id>/`; `<output_dir>/latest.json` is a pointer, not a duplicate result. The manifest includes schema version, status, timestamps, fingerprint, provenance and required artifacts.
- Core run artifacts: `config.json`, `qc.json`, `manifest.json`, `splits.json`, `predictions.csv`, `metrics.json`, `model.bmpmodel`, `stability.csv`, `panel_comparison.csv`, `model_comparison.csv`, `report.html`, `report.pdf`, and `figures/`. Conditional artifacts and failed metrics must be declared explicitly.
- Executable CLI commands: `validate`, `analyze` (`binary`/`survival` aliases), `predict`, `evaluate`, `runs`, `compare`, `resume`, `report`, `doctor`, `ora`. `--json` emits machine-readable summaries; progress uses `BMP_EVENT:` JSON lines on stderr. All commands return nonzero on failed operations.
- GUI calls the same engine and consumes the same JSON artifacts; existing R entrypoints become thin compatibility wrappers.
- Minimal core dependencies: R, yaml, jsonlite, digest, survival, glmnet, pROC; plotting/report dependencies must be explicit. Pathway dependencies stay optional for core analysis.
