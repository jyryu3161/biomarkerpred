# BioMarkerPred v0.5.1

This patch repairs Docker setup and diagnostics in the desktop application. When Docker Desktop's Linux engine cannot be reached, v0.5.0 incorrectly reported that the configured analysis image was unavailable. The new diagnostics distinguish the Docker executable, engine connection/container mode, and analysis image, and retain the original command error.

## Changes

- Settings provides an explicit **Download analysis image** action. It saves the selected executable/image and automatically checks the actual analysis engine after downloading. Only a successful doctor check reports runtime readiness.
- Docker Desktop installation/start guidance and separate **Docker Engine** / **Analysis Image** states explain the next action. A missing Windows `dockerDesktopLinuxEngine` pipe is a connection failure; the image is not marked missing without a successful Linux engine connection.
- Downloads allow up to 30 minutes instead of five. Pending downloads/checks remain protected when navigating away and back, and stale diagnostic responses cannot overwrite a newer result.
- Local R remains independent of Docker. Checking runtime is read-only; it does not pull images, start Docker Desktop or change Docker contexts. Scientific algorithms and model/interface formats are unchanged.

## Installation and recovery

Windows x64 users can install either the attached NSIS `.exe` or MSI. Start Docker Desktop and wait for its Linux engine to be running. In BioMarkerPred Settings choose Docker and select **Download analysis image**. Downloading and the subsequent engine check run together. Existing saved custom runtime settings are preserved; a previously configured v0.5.0 image remains compatible with this diagnostic patch. Fresh settings use `jyryu3161/biomarkerpred:v0.5.1` (Linux amd64).

If Docker Desktop reports that its engine is running but BioMarkerPred cannot connect, inspect **Docker command diagnostics** and check the selected executable, Docker context and permissions. Reinstalling the analysis image cannot repair an unreachable Docker engine. See [Docker's daemon troubleshooting guide](https://docs.docker.com/engine/daemon/troubleshoot/) and [Windows installation guide](https://docs.docker.com/desktop/setup/install/windows-install/).

## Verification and scope

Publication requires the same source commit to pass scientific acceptance, frontend tests/lint/build, Rust process and Docker integration, browser interactions, production-image tests and every desktop platform gate. Added regression checks cover the reported Windows named-pipe error, missing/denied image inspection, engine disappearance, Windows-container mode, custom executable paths, download failure, doctor failure and stale UI checks.

Windows Server 2022 gates install MSI and NSIS separately and run real native IPC and local R analyses with spaces/Korean paths, graphics and process-tree cancellation. These checks do **not** run Docker Desktop on Windows. Docker daemon/image integration is exercised on Linux; Windows connection-error behavior is also covered by controlled diagnostic fixtures. The release does not claim direct access to or verification of the affected user's machine.

The Linux gate installs and exercises the Debian package; RPM and AppImage are built. The macOS gate runs Apple Silicon R/Rust, verifies the mounted DMG and launches the application; the Intel slice is built but not executed, and native macOS WebDriver IPC is not tested. Packages remain unsigned/unnotarized. Source identity, image digest, installer checksums and successful workflow provenance are attached/generated below.
