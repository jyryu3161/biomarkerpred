# BioMarkerPred v0.4.3

This maintenance release starts from v0.4.2 and retains its train/test selection design and desktop interface. v0.5.0 and v0.5.1 have been withdrawn. Their nested cross-validation, external-validation and report extensions are not included. No v0.5.x post-download validation or timeout changes are backported; the existing v0.4.2 status refresh is retained.

## Confirmed fixes

- Survival predictions apply the cutoff saved when fitting the model. A patient's risk group is unchanged when other patients are added to the prediction batch. Older survival artifacts without a saved cutoff must be retrained; a cutoff is never guessed from new patients.
- Unavailable survival AUCs stay `NA` (JSON `null`) with an explicit reason in saved results and the GUI. A measured AUC of zero remains zero. If no candidate has an available training AUC, the process fails and retains diagnostic CSVs without saving a successful model.
- Docker checks distinguish a missing executable, an unreachable engine, Windows containers, an image that is absent, and an image-inspection failure. Late responses from older environment checks cannot overwrite the current state.
- Single-gene survival results preserve a valid formula and predictor dimensions through model saving and plotting. Failed survival selection or model saving is reported as failure.

The application, launchers and Docker update check target `jyryu3161/biomarkerpred:v0.4.3`. The image inherits the exact v0.4.2 runtime at `sha256:f865534ce6757662a6214339bf0710473bd377d0459b3df9ddad04c8bd30a7c6` and replaces only the application R sources and entrypoint. Dependency locks and the saved-model format version are unchanged apart from application-version metadata.

## Observed verification

All analysis fixtures were synthetic. Local checks exercised the real v0.4.2 Docker R runtime, including nsROC/Cox fitting, model saving and CLI prediction, single-versus-batch invariance, missing-AUC diagnostics, and all five legacy survival plotting functions producing six fresh SVGs. Full 120-row binary and survival workflows completed. The survival fixture had 67 events, produced seven SVGs (the stepwise figure plus six result graphs), and saved a validated model; coefficients, AUCs and cutoff were unchanged by the plotting repair. That final model gave the same synthetic patient risk score (0.064588) and Low group alone and in a three-patient batch. An unsupported survival horizon exited with status 1, retained reason CSVs and produced no model.

The frontend passed 34 tests and its production build; Rust passed 36 tests, including controlled Docker-status cases. Repository lint still reports 14 existing errors (15 in the baseline); whole-repository Rust formatting also has pre-existing failures, so only touched regions were formatted. These checks do not establish all-platform desktop behavior. Windows Docker Desktop was not tested on a real Windows installation, and no new cross-platform installer verification or v0.4.3 publication is claimed by these local checks.

The GUI workflow builds installers and creates a draft release after frontend and Rust tests. Docker CI tests the loaded candidate image before a version/latest push; manual dispatch defaults to no publication. A CI build is separate from installed application verification. macOS artifacts use ad-hoc signing and are not notarized.
