# Scientific acceptance checks

These checks are independent acceptance criteria for the implementation roadmap. They are not claims that the tests already exist or pass.

1. **Assessment perturbation isolation:** with a fixed outer split, change only assessment predictors/outcomes. The fitted preprocessing, candidate list, coefficients, hyperparameters and threshold for that split must remain identical. Assessment metrics may change. Do not apply this assertion to the other outer folds in which those rows are legitimately training data.
2. **Grouping:** no patient/group appears in both sides of any outer or inner split. Repeated samples retain distinct sample IDs. Resampling and uncertainty procedures respect the configured grouping.
3. **Model choice:** when selecting among algorithms, feature sets or panel sizes, choose within inner CV for every outer fold. Report the outer performance of that selection procedure separately from the descriptive comparison of fixed model arms. Do not relabel the best outer-CV arm's score as an unbiased estimate of adaptive model selection.
4. **Frozen transformations:** numeric imputation/scaling and categorical levels are fitted on the training partition. An unseen category produces a documented error or predeclared unknown-level policy, never a silently re-fitted encoder.
5. **Prediction roundtrip:** native fitted binary/Cox/elastic-net predictions agree with the serialized artifact, including coefficients, design columns, centering and survival baseline hazard. Compare a single sample, a full batch and reordered columns/rows. Preserve sample IDs including leading zeros.
6. **Threshold semantics:** binary class coding and display names are explicit; survival risk-group boundaries are frozen. Adding other patients to an input batch cannot change an existing patient's score, survival probability or class.
7. **External evaluation:** model bytes/checksum remain unchanged; no external outcomes are used to choose features, hyperparameters or thresholds. Prediction works without outcome columns; evaluation requires them. Cohort distribution diagnostics do not alter the fitted pipeline.
8. **Censoring:** use censoring-aware survival discrimination, Brier/calibration and horizon support checks. Samples censored before a horizon cannot be treated as observed negatives. Report unavailable estimates and reasons; never replace failures with zero. Check a no-censoring case against ordinary binary Brier at a fixed time.
9. **Known metric examples:** binary ROC AUC and average precision agree with independent calculations; a constant probability yields its exact Brier score; DCA treat-none equals zero; survival probabilities stay within [0,1] and are non-increasing over time.
10. **Uncertainty:** intervals describe their sampling unit and method. Repeated held-out predictions from one patient are not counted as independent patients. Report effective sample counts and failed resamples.
11. **Run isolation:** independent invocations never consume one another's intermediate files. Completion requires required artifacts and valid model metadata. Invalid data, fitting failure, cancellation and report failure have distinct observable outcomes.
12. **Resume and workers:** unchanged interrupted runs reuse only completed compatible checkpoints. Changed data/config/engine rejects resume. Serial and parallel execution produce equivalent splits and numerical outputs within stated tolerance. Resource limits and cancellation reach worker processes.
13. **Pathways:** original and expanded sets are identifiable; measured/eligible background is explicit and mapped with diagnostics; enrichment excludes outside-universe genes with counts. STRING neighborhood expansion is requested explicitly. GSEA uses a real ranked statistic, not a shuffled selected-gene list.
14. **Interfaces:** CLI and GUI normalize equivalent settings to the same analysis configuration. CLI validation/history/comparison/reporting are independently usable. GUI controls must affect engine behavior and displayed results must come from the actual run directory.
15. **Research export:** HTML and PDF contain the same run identity, cohort/validation description, model results, unavailable metrics/warnings, gene panel and provenance. Figures reuse stored assessment predictions and clearly label exploratory development-data plots.

## Independent numerical examples for metric review

- Binary outcomes `0,0,1,1` with probabilities `0.1,0.4,0.35,0.8`: ROC AUC is `0.75`, average precision (step-wise recall integration) is `5/6`, Brier score is `0.158125`. At a `0.5` decision threshold sensitivity is `0.5`, specificity is `1`. DCA model net benefit is `0.4375` at threshold `0.2` and `0.25` at threshold `0.5`; treat-none is zero. State whether PR-AUC means average precision or trapezoidal area.
- At horizon `3`, uncensored survival times `1,2,4,5` imply event indicators `1,1,0,0`. Predicted event probabilities `0.8,0.6,0.3,0.1` have Brier score `0.075`. A censor-aware estimator with censor survival equal to one must reproduce it exactly.
- At horizon `3`, times `1,2,4,5` and events `1,0,1,0` leave row 2 unobserved at the horizon. For a declared training censor curve with `G(1-)=1` and `G(3)=0.5`, event-probability predictions `0.8,0.6,0.3,0.1` give the standard IPCW Brier estimate `(0.04 + 0 + 2*0.09 + 2*0.01)/4 = 0.06`. Row 2 contributes no observed-negative term. A normalized weighted average has different semantics and must not be mislabeled as this estimator.
- For all of these examples, duplicating rows across repeat identifiers must not double the number of independent patients used to describe uncertainty. Cluster resampling retains all rows belonging to a sampled patient.
- Reverse Kaplan–Meier tie example: times `1,1,2,3`, events `1,0,1,0`. Remove observed events before the tied censoring failures: `G(1)=2/3`, `G(2)=2/3`, `G(3)=0`; the event at time 1 uses left limit `G(1-)=1`.

Reference definitions checked during implementation: [IPCW Brier score](https://scikit-survival.readthedocs.io/en/stable/api/generated/sksurv.metrics.brier_score.html), [cumulative/dynamic AUC](https://scikit-survival.readthedocs.io/en/stable/api/generated/sksurv.metrics.cumulative_dynamic_auc.html), and [reverse Kaplan–Meier tie convention](https://scikit-survival.readthedocs.io/en/stable/api/generated/sksurv.nonparametric.kaplan_meier_estimator.html). The stored training censoring distribution assumes an applicable, independent censoring process; support and distribution limitations must be visible in external evaluation.

## Independent pathway review examples

- Universe A through J (10 genes), original query A/B/C, term A/B/D: the one-sided hypergeometric enrichment probability is `(choose(3,2)*choose(7,1) + choose(3,3)*choose(7,0))/choose(10,3) = 22/120`. Query or term genes outside the declared universe must not inflate its numerator or denominator. Record any annotation-mapping restriction separately; this oracle assumes all 10 universe genes are mapped.
- Ranks A through J with statistics `5,4,3,2,1,-1,-2,-3,-4,-5`: weighted running-sum enrichment has ES `+1` for A/B and `-1` for I/J. A complete-universe set has no miss denominator and must be explicitly unavailable. Null permutations must use the full eligible ranked list, with seed and permutation type recorded; selected-only inputs cannot be described as full-ranked GSEA.
- Mock a STRING network with original A/B, added measured D, and added unmeasured K. Preserve original A/B and expanded A/B/D/K separately. The network may show K, but its absence from the assay universe must be visible and enrichment must not silently add K to the measured background. Store explicit `add_nodes`, mapping coverage, source version, request parameters and response hashes.
- Repeat the network example with assay source IDs mapped to annotation symbols (for example source `ENSG_D` maps to symbol `D`). A returned original-node alias is not a new interactor. A returned added `D` that maps unambiguously to the measured QC assay remains eligible for expanded-query ORA; an unmeasured `K` stays excluded. Graph/evidence membership flags must use this same declared mapping, without counting aliases twice.

Primary API references: [STRING API](https://string-db.org/help/api/) documents identifier mapping and explicit `add_nodes` for text/JSON network expansion; [fgsea tutorial](https://bioconductor.org/packages/release/bioc/vignettes/fgsea/inst/doc/fgsea-tutorial.html) demonstrates pathway analysis from a named full gene-statistic vector and reports ES/NES, p-values and leading edges. These references do not validate any implementation by themselves; the numerical and provenance checks above remain required.

For running-sum edge cases, the primary [fgsea statistic implementation](https://github.com/alserglab/fgsea/blob/master/R/fgsea.R) uses a neutral score and empty leading edge for equal positive/negative excursions, uniform hit increments when all hit weights are zero, and rejects a complete-universe gene set. The platform must declare its numerical tie tolerance; independent tests also check these edge cases.

## Desktop integration review cases

- Invoke the real CLI through the Rust runner with the locked R runtime, from a directory unrelated to the engine. A valid configuration produces the same normalized settings and QC as direct CLI execution. Invalid QC returns its structured errors to the interface.
- A zero-exit child that omits its JSON result, reports an unfinished manifest, or references a missing/tampered required artifact must not produce analysis success. Report-only success preserves the source run's existing status.
- Start a job and attempt another mutation before process registration completes; the second must be rejected. Cancel during startup and during execution. Late events from the cancelled token cannot complete a later job.
- Run `fixtures/worker_process_tree.R` through the same process-launch/cancellation primitive used by production. Wait for `ready`, cancel, and verify the parent and both PSOCK PIDs have stopped. For pathway cancellation, only its derivative manifest is cancelled; the completed development manifest remains byte-identical.
- Read a CSV with a BOM, a quoted comma in a gene name, an embedded newline in a cell, leading-zero IDs and an integer-shaped ID longer than JavaScript's exact integer range. Preserve identifier strings. Load a valid intercept-only binary/Cox artifact; reject an incomplete legacy artifact with a retraining explanation. Saving to the same canonical model file preserves its bytes.
- A local R executable missing a required package and an existing Docker image with an incompatible doctor response are unavailable runtimes. A compatible local runtime works when Docker is absent. User executable/image settings affect checks and execution consistently.
- Docker runs with input, evidence, model and output in separate directories containing spaces return host-resolvable paths. A second compatible Docker invocation can resume from saved paths; the inspected image ID is in provenance. Cancellation stops the named container and its workers before releasing the job.
- An engine staged into a temporary resource directory, without access to the checkout as its engine root, supports doctor/validation and preserves the same code-file hash set. Packaged macOS/Windows execution requires separate evidence; a Linux container or mocked browser does not establish it.

## GUI workflow review cases

- Defaults come from the installed schema, including survival-specific defaults. Column selections preserve exact names, including commas and newlines. Outcome coding, labels, group and clinical columns, nested folds, repeats, workers, panel candidates and evidence settings reach the shared validation request unchanged. Import uses normalized CLI configuration; editing invalidates prior QC.
- A compatible local runtime permits validation and analysis without Docker. Persistent settings select the same executable/backend for doctor and subsequent operations. Readiness errors remain visible with a route to settings.
- Subscribe before starting and recover a completed snapshot after start. A deliberately immediate completion is visible; a delayed previous-job event is ignored. A second mutation is disabled across every page. Cancellation remains busy until confirmed, and unverified termination offers retry without claiming success.
- Open a completed run, a failed/partial run and a run with an integrity error. Show their actual identity/status, available QC and warnings, and integrity diagnostics. Render unavailable metrics and confidence limits with reasons rather than zero. Separate adaptive primary performance from descriptive fixed-arm comparisons and external evaluation.
- Load valid binary and Cox null models. Display frozen requirements, coding, thresholds and horizon without assuming a selected-gene count greater than zero. Prediction accepts data without outcome columns; evaluation calls the distinct frozen-model operation. Preserve long and leading-zero IDs in result tables.
- Scan saved run history, reopen a run after navigation, compare compatible and incompatible cohorts, resume, and open/export the recorded HTML/PDF/figure paths. These actions must use the selected actual run directory, not a configured output root or legacy fixed filenames.
- Start a pathway derivative using versioned local annotation and explicit network settings. Display original/expanded/background counts, mapping exclusions, ORA and ranked GSEA independently. Inspect shared/mapped network nodes through structured assay mappings; preserve nullable evidence scores and interaction channels. Confidence filtering, search, dragging and gene details remain usable with exact identifier strings.
- Fetch and reuse immutable Open Targets snapshots while retaining disease/ontology context. Distinct fetches must not overwrite a file already referenced by a saved configuration. The old `efo_id` field accepts returned MONDO IDs as well as EFO IDs.

Browser checks using injected Tauri IPC exercise frontend behavior and contract consumption. They must be reported separately from real Rust/CLI integration and native desktop execution.

## Installed-runtime review cases

- Build the production Docker image from its pinned runtime and allowlisted context. Mount synthetic data only, compare packaged engine hashes with the checkout, and exercise binary/Cox analysis, frozen scoring/evaluation, compatible resume and report regeneration. Confirm exact identifiers, time-unit rejection, artifact integrity and searchable Unicode PDF text. Development runtime provenance is under `environment`; external evaluation uses `evaluation_engine`.
- Build and install the Linux desktop package without mounting repository source. Use actual WebDriver/Tauri IPC to resolve the installed engine, validate a cohort, run analysis, inspect verified artifacts and score a valid null model. Supply R separately as documented. Record any test-container adjustments and distinguish this native execution evidence from simulated browser IPC, optional screenshot capture and untested operating systems.
