# BioMarkerPred CLI and contributor workflow

Follow [AGENTS.md](AGENTS.md) for the sequential subagent implementation / primary-review agreement, scientific invariants, file ownership and verification. [README.md](README.md) contains executable binary/survival, prediction, external evaluation, history and pathway workflows. [docs/implementation-roadmap.md](docs/implementation-roadmap.md) records actual implementation and review status.

Operate through `BiomarkerCLI.R` or `run_analysis.sh`, the same engine as the desktop. On Linux x86_64, install the exact root Pixi lock with `./install.sh` (Pixi 0.71.2), run `doctor --json`, inspect the configuration/input headers, then `validate --config CONFIG --json` before `analyze`. Set `BMP_RSCRIPT` to an executable path when needed. Do not install ad-hoc CRAN packages, assume Docker is required for local R, or silently change the lockfile.

Save the normalized configuration/QC response. Read the actual `run_id`, `run_dir` and `paths` from JSON, inspect the manifest/status and required hashes, and only then summarize results. Commands exit nonzero for failed operations; stderr carries `BMP_EVENT:` progress, while `--json` stdout is one result object. Retain partial/failed artifacts and explain their warnings. Report cohort sizes, validation method, failed folds, model and report paths.

Use synthetic fixtures for development. Keep outer assessment and external cohorts out of preprocessing, screening, model/panel tuning and threshold selection. Preserve exact sample IDs, patient groups, outcome codes/labels, and survival units/horizon. Frozen prediction/evaluation cannot refit the model. Missing metrics stay unavailable with reasons; conditional patient bootstrap intervals do not include model-selection uncertainty.

Use `report` for no-refit regeneration and `resume` only with compatible input/config/code/runtime/evidence and verified artifacts. Never displace a live lock or report unverified process termination as successful cancellation. Old incomplete model files require retraining; do not fabricate missing encoders, thresholds or Cox baselines.

For pathways, start from a completed verified development run, retain measured/mapped backgrounds and full ranked GSEA, and separate original/expanded genes. STRING requests use public identifiers; added unmeasured nodes do not enter ORA statistics. Open Targets snapshots are immutable disease-gene associations with exact symbol/Ensembl matching, not drug-response evidence. Legacy Streamlit/train-AUC/coexpression/drug-score workflows are retired.

Use the executable checks listed in AGENTS.md. Browser IPC simulation, actual Rust/R/Docker orchestration, installed Linux desktop execution and native macOS/Windows execution are distinct evidence. State precisely which passed. Routine local work does not imply permission to publish. The current user explicitly authorized v0.5.0 remote CI/release/Docker deployment, with the primary session reviewing and performing remote mutations. Never upload patient data.

## Authorized release verification

Synchronize an explicit application version with `scripts/sync-version.sh v0.5.0`, then `node scripts/check_release_version.cjs v0.5.0`. Scientific engine/interface/model versions are independent. The release workflow uses one source SHA, never moves an existing tag, and defaults manual dispatch to `publish=false`. Publication requires the scientific CI, every desktop platform gate and installed-image checks. A published version is immutable; use a new version for changed artifacts. Docker Hub remains `jyryu3161/biomarkerpred`; launchers/default settings select the versioned published image and pull only explicitly.

Windows must pass actual installed MSI and NSIS IPC, binary/Cox R workflows, Cairo graphics and PSOCK/taskkill termination; a successful build alone is insufficient. macOS currently verifies Apple Silicon R/Rust, the mounted DMG's engine and app launch; native WebDriver IPC/Intel execution are not claimed. Native package hashes live in `tests/runtime/native-r-lock.json`, separate from Linux's conda lock. Use only synthetic data on hosted runners. Release notes/checksums record the exact source and registry image digest, signing limitations and observed verification scope.
